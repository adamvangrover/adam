# Meta Muse & Muse Spark Guidelines — AFOS v30.1 Operational Standards

## 1. Overview & Context
This specification outlines operational standards for **Meta Muse** and **Muse Spark** closed-weights reasoning models interacting with the **ADAM Financial Operating System (AFOS v30.1)**.

Meta Muse is designed for high-density thought compression and multimodal institutional financial synthesis. In AFOS, Muse models operate within both System 1 perception loops and System 2 neuro-symbolic arbitration layers.

---

## 2. Core Architectural Principles

### A. Thought Compression Token Budgeting
- **Inference Efficiency:** Utilize thought compression techniques to minimize reasoning overhead while maintaining rigorous validation steps.
- **Budget Allocation:** Reserve explicit token margins for W3C PROV-O audit trails and JSON-serialized proof-of-thought outputs.
- **Epistemic Classification:** Label reasoning outputs using AFOS standard tags:
  - `[VERIFIED]`: Grounded directly against immutable source filings (10-K, 10-Q).
  - `[CALCULATED]`: Deterministically evaluated through mathematical formulas or `jsonLogic`.
  - `[MODEL_EST]`: Probabilistic estimation generated by neural weights.
  - `[PENDING]`: Unresolved hypothesis requiring secondary verification.

### B. Probabilistic-to-Deterministic Integration Layer (PDIL)
- Muse inferences must pass through the PDIL Gatekeeper (`src/pdil/middleware.py`).
- **Grounding Verification:** Every model output must pass `check_grounding()` by explicitly linking claims to a valid `source_data_object`.
- **Confidence Calibration:** Conviction scores below `0.85` trigger Human-in-the-Loop (HITL) review. Scores below `0.50` result in hard rejection.

### C. Environmental Bifurcation
- **Path A (`core/`, `adam_*/`, `src/`):** Strict types, zero hallucinations, immutable append-only logs.
- **Path B (`experimental/`, `research/`, `tinker_lab/`):** Rapid exploratory workflows. Never cross the boundary into Path A.

## 3. Tool Calling & Execution Workflows
Muse agents should call registered MCP tools defined in `mcp.json`:
- `retrieve_market_data`: Fetching real-time market tickers and volatility structures.
- `financial_statement_parser`: Deterministic XBRL metric extraction.
- `covenant_headroom_calculator`: Stateless covenant stress testing.
- `arbitration_calculator`: Dual-model credit rating consensus.

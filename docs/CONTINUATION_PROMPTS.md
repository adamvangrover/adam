# Continuation Prompts

Copy-paste prompts for picking up the modernization work in a fresh agent session. Each one is
self-contained: it names the branch base, the files, the gate to pass, and what not to touch.
These are starting templates — pick one, refine to taste.

Shared rules for every prompt below:

* Branch off `main` in `adamvangrover/adam`; one PR per prompt; do **not** merge.
* Path A (`core/`, `adam_os/`, `services/`, `server/`, `config/`, `schemas/`) never imports Path B
  (`research/`, `core/experimental/`, `archive/`). `tests/unit/test_architecture_boundaries.py` enforces it.
* No `eval`/`exec`/`pickle.load` in Path A; no hand-edited lockfiles; never overwrite `mcp.json`;
  no new top-level directories without a tag in `machine_index.json` → `directory_map`.
* Generated artifacts (`showcase/manifest.json`, `showcase/catalog.html`, `showcase/dashboards/index.html`,
  `showcase/browser/`) are regenerated by their script, never hand-edited.
* Gate: `make verify-quick` (or `bash scripts/verify_repo_health.sh --skip-sync --quick`) plus
  `ruff check <changed files>`.

## 1. Work down the test quarantine

> Read `tests/quarantine.txt`. For each entry, run it in isolation
> (`pytest <id> -p no:randomly`). If it passes alone but fails in the suite, find the test that leaks
> into `sys.modules` and fix the leak with `monkeypatch`/fixtures. If it fails alone, fix the code or the
> stale test. Remove fixed entries from the quarantine file (XPASS shows them). Batch ~20 per PR.

## 2. Backfill newsletter / briefing editions (data first, then HTML)

> Families: Market Mayhem, Daily Briefing, Market Pulse, House View (see `showcase/catalog.html`,
> filter by family, and `docs/TEMPLATES.md`). For one family: list edition dates present in
> `showcase/manifest.json`, pick the generator that produced the newest edition (grep `scripts/` and
> `core/newsletter_layout/` for the filename pattern), and generate missing editions as structured data
> (JSON/MD with `_estimated: true` on hand-picked values per `docs/PROVENANCE.md`) before rendering HTML.
> Add a regression test that the generator output validates against its schema. Regenerate the catalog:
> `python scripts/build_dashboard_manifest.py --root showcase --hub catalog.html --include dashboards apps
> portal status_terminal events widgets templates archive_v2`.

## 3. AFOS / Adam OS terminal refinement

> Filter the unified showcase to family `afos` / `adam_os` and kind `terminal`. Pick the newest
> generation as the reference, diff it against older variants, and extract shared CSS/JS into
> `showcase/js/` + `showcase/css/` without changing behaviour. Keep terminals presentation-only: any
> data they show must come from JSON under `showcase/data/`, not inline literals. Screenshot before/after.

## 4. Showcase catalog follow-ups

> `scripts/build_dashboard_manifest.py` + `scripts/templates/showcase_catalog.html.tmpl`. Ideas:
> reduce the `other` family (inspect its titles, add `_FAMILIES` patterns, extend
> `tests/unit/test_build_dashboard_manifest.py`); add a CI check that the committed manifests are fresh
> (regenerate and `git diff --exit-code`); link `catalog.html` from `showcase/index.html`.

## 5. Open-PR backlog

> Read `docs/PR_TRIAGE_REPORT.md`. Re-verify the P0 list against current `main` (some may now conflict
> or be superseded). Rebase P0 PRs in the listed merge order and report CI per PR. Do not close or merge
> any PR without the owner's explicit approval.

## 6. Nexus dispatcher consolidation

> `AGENTS.md` names Nexus as the sole dispatcher; the code entry point is
> `core/engine/meta_orchestrator.py::MetaOrchestrator`. Inventory every other orchestrator/dispatcher in
> `core/engine/` and `core/agents/orchestrators/`, document which are live (imported from an entry point)
> vs dead, and propose — don't execute — a consolidation plan as `docs/` markdown.

## 7. Environment blueprint

> `scripts/verify_repo_health.sh` (no flags) installs `requirements/base.txt` plus test deps on top of
> `uv sync`. Make the repo blueprint run the same install so fresh sessions can run the full suite, then
> confirm `make verify` collects with zero import errors.

# ADAM Showcase

`showcase/` is the **presentation layer**: static HTML/JS pages (GitHub Pages root) that run in a browser
with no backend, plus optional live features when the API is up. Nothing here is imported by execution
code (`core/`, `services/`, `server/`).

> **These are starting templates — pick one, refine to taste.** The brands, newsletters, terminals and
> portals here are parallel defaults, not a single canonical UI. Paths, purpose and what to customize for
> each family: [docs/TEMPLATES.md](../docs/TEMPLATES.md).

Related: [README](../README.md#-templates--brands) · [REPO_MAP §1](../REPO_MAP.md#1-canonical-tree) ·
[Setup Guide — Slice A/F](../docs/setup_guide.md#slice-a--static-showcase-only-no-install)

## Template families & manifest classification

About 540 HTML pages live at the `showcase/` root, plus subdirectories. They group into families by
filename:

| Family | Pattern | Count (approx.) | Catalog |
|---|---|---|---|
| Daily briefings | `Daily_Briefing_YYYY_MM_DD.html` | ~100 | [TEMPLATES §3](../docs/TEMPLATES.md#3-newsletter--report-families) |
| Market pulse | `Market_Pulse_YYYY_MM_DD.html` | ~65 | §3 |
| House view | `House_View_YYYYMMDD.html` | ~15 | §3 |
| Market Mayhem editions | `newsletter_market_mayhem_*.html`, `Market_Mayhem_*.html`, `market_mayhem_*.html`, `market_mayhem_archive/` | 60+ | §2–§3 |
| Analyst OS shells | `analyst_os*.html`, `unified_analyst_os.html` | 4 | §2 |
| Terminals / institutional OS | `dashboards/adam_v30_*`, `dashboards/adam_v31_0_*`, `dashboards/*terminal*` | ~9 | [§4](../docs/TEMPLATES.md#4-terminal-variants) |
| Portals / hubs | `portal/`, `dashboards/hub.html`, `dashboards/index_*.html` | ~10 | §2 |
| Reports & deep dives | `report_*.html`, `credit_memo*`, other one-offs | — | — |

Both catalogs are generated by `scripts/build_dashboard_manifest.py`, never hand-edited. The page shell
lives in `scripts/templates/showcase_catalog.html.tmpl`; edit it there and regenerate:

```bash
python scripts/build_dashboard_manifest.py   # dashboards/manifest.json + dashboards/index.html
python scripts/build_dashboard_manifest.py --root showcase --hub catalog.html \
    --include dashboards apps portal status_terminal events widgets templates archive_v2   # unified showcase
```

Each `manifest.json` entry has `path`, `title` (from `<title>`), `kind`, `family`, `section` (`root` or the
subfolder) and, when the filename carries one, an ISO `date` (`2026_03_27`, `20260329`, `03292026`,
`dec_2024`, `mar_16_2026`).

* `kind` is the page shape, by the first matching filename substring: `index` (`index`, `hub`, `readme`),
  `terminal` (`terminal`, `_os`, `ide`, `studio`, `workbench`), `viewer` (`viewer`, `visualizer`, `map`,
  `graph`, `gallery`, `explorer`, `browser`), else `dashboard`.
* `family` is the template family, by the first matching pattern in `_FAMILIES` (specific before broad):
  Market Mayhem, Daily Briefing, Market Pulse, House View, Newsletter, AFOS, Adam OS, Credit, Scenario,
  Research, Eval/Governance, Agents, Operations, Hub, Publications (schema terminals, reports, outlooks),
  Valuation, Markets, Knowledge, Platform, else `other` (0 pages today;
  `test_committed_showcase_has_no_unclassified_pages` keeps it there).
* CI (`.github/workflows/showcase-manifest-fresh.yml`) regenerates both catalogs, re-applies the kit and
  `scripts/harden_adam_daily.py`, then fails on `git diff --exit-code -- showcase`. Commit regenerated
  output with any page change.

### Schema editions (`data/publications/`)

Apr–Nov 2026 editions are `Edition` JSON records (+ MD, + HTML at the family's usual filename) generated
from the synthetic `data/scenarios/2026H2_path.json`; every one is `_estimated: true`. Edit the YAML in
`config/` or the templates in `templates/publication/`, never the output, then run
`python scripts/publications/backfill_editions.py` and rebuild the catalogs. Coverage:
[`docs/CONTENT_COVERAGE.md`](../docs/CONTENT_COVERAGE.md).

The unified catalog is the machine-readable inventory for the UI/UX overhaul (Phase A): pick a family,
open the newest edition as the starting template, and use **copy path** to clone it. `deprecated_archive/`
is intentionally left out.

## Repo browser (`showcase/browser/`)

`scripts/generate_directory_indexes.py` builds an "Index of" page for every repository directory, with
file listings and an embedded `README.md` preview. It writes **only** into `showcase/browser/<path>/index.html`
(mirroring the tree) and links back to the real files, so source directories such as `core/` stay free
of generated HTML.

```bash
python scripts/generate_directory_indexes.py      # ~1,000 pages, ~15 MB
open showcase/browser/index.html
```

The output is a regenerable artifact and is git-ignored; generate it locally or in a Pages build step.

## Live mode

Pages work from the filesystem (static mode). Features that call the API need the backend
(`python services/webapp/api.py`, port 5001, or the Docker stack) — see the
[Setup Guide](../docs/setup_guide.md#slice-g--docker--full-stack). Pages that `fetch()` JSON need to be
served over HTTP (`python3 -m http.server 8080 --bind 127.0.0.1` from the repo root; never expose it on other interfaces, since the server would also publish `.env`) rather than opened via `file://`.

## Adding or forking a page

1. Copy the closest template (see [docs/TEMPLATES.md](../docs/TEMPLATES.md#how-to-fork-a-template)).
2. If it lives in `dashboards/`, rerun `scripts/build_dashboard_manifest.py`.
3. If root `index.html` links to it, run `.venv/bin/python -m pytest tests/unit/test_standalone_distribution.py -q`.
4. Keep presentation logic here; never import UI code into `core/`.
